## A useful practice rotation

1. **Coding:** solve an exercise, run the cases, explain the invariant, and identify an input your own tests missed.
2. **Project defense:** attach the actual repository or document. Explain one decision, an alternative, and evidence that the project worked. Source questions cite imported material; unsupported project tests are reported as unavailable.
3. **Quant or finance:** state assumptions before calculating. Distinguish a reference calculation from a conclusion that depends on uncertain inputs.
4. **Behavioral:** explain the situation, your own contribution, the result, and what you would change. Use real experience and keep confidential details out of shared demos.
5. **Review:** return to the session report and choose one weak explanation to practise again. A passed example or positive model response is evidence from that attempt, not a hiring score.

Start with ordinary practice. Timed assessments remove hints; strict SEB adds a separate device policy when you want exam-style conditions. Neither is required to import a resume or receive model feedback.
